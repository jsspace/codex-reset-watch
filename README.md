# Codex Reset

Track Codex resets with probability badges and timely alerts.

监测 Codex 公开额度重置消息的 Chrome 扩展，重点是无需点击即可看到的工具栏角标，以及重要消息的强提醒。

## 产品需求

- 固定到 Chrome 工具栏后，持续显示当前状态。
- 有可信预测数据时，角标显示 `95%`、`99%` 等概率，点击可查看预测时间范围、来源与更新时间。
- 工具栏角标优先提示高概率时间窗；公告仍通过通知展示原文链接。
- 有可靠执行证据时，显示 `已重置`，与“已宣布”分开处理；公开重置事件不代表每个账户均已恢复额度。
- 数据过期或获取失败时，显示灰色 `?`，不继续展示旧的高置信状态。
- 强提醒包含桌面通知、可选提示音，以及用户可配置的重复提醒间隔。
- 同一事件需要去重，不显示未读或已读状态。

## 数据规则

- 不凭空生成概率；没有可靠概率来源时，使用明确状态。
- 第三方概率必须标明来源、预测时间范围和更新时间，不能当成官方保证。
- 区分“预测”“官方已宣布”“已执行”三种状态。
- 开发前先确认消息源的可用接口、访问规则和数据有效期。
- 首版聚焦公开重置消息，不读取 Codex 账户凭证，不执行账户重置。

## 技术方向

- Chrome Extension Manifest V3。
- 使用 `chrome.action` 更新角标、颜色和悬停说明。
- 使用 `chrome.alarms` 定期检查，使用 `chrome.storage.local` 保存设置、缓存和已读状态。
- 使用 `chrome.notifications` 发出桌面提醒。系统通知权限和勿扰模式可能影响提醒效果；浏览器完全退出或电脑休眠时不能保证及时检测。
- 提示音作为可选能力，遵守扩展后台生命周期和播放要求。

## 当前进度

首版 Manifest V3 扩展已实现，直接接入 [codex-reset.com](https://codex-reset.com/) 的公开 forecast 和 timeline API。无构建依赖，无需账户凭证或 API Key。

### 本地加载

1. 打开 Chrome 的 `chrome://extensions`，开启“开发者模式”。
2. 点击“加载已解压的扩展程序”，选择本项目的 `extension` 文件夹。
3. 将 **Codex Reset** 固定到工具栏。首次加载会立即检查，此后每分钟检查一次。
4. 点击工具栏图标查看概率、来源原文和更新时间，通过顶部设置按钮调整通知、声音、概率阈值及重复提醒。

角标显示：按浏览器本地日期，今天已有重置记录时，后续预测达到 90% 则优先显示 `明`，否则显示 `今`。今天没有重置记录时，未来 24 小时概率达到 90% 显示 `今`，否则未来 48 小时达到 90% 显示 `明`，其余显示 `46%` 等 24 小时预测；灰色 `?` 表示未知或过期。预测的 `今` / `明` 是滚动时间窗的简写，24 小时可能跨过本地午夜，48 小时也包含今天，不能当成确定的自然日；悬停可查看实际窗口和概率。手动刷新也遵守一分钟请求间隔和限流退避。

当前稳定 API 不足以独立证明执行完成，因此首版**不显示“已重置”**；公告与信号也不代表你的账户额度已经恢复。Banked reset 不混入直接重置提醒。

### 界面与语言

首页将今天的状态与最近重置记录合并在同一主卡：有公开记录则显示本地时间、日期与距今时间，否则给出明确标注的未来 24 小时概率。主卡直接给出“今天已有重置记录”等结论，将时间与距今时长放在同一组，日期与本地时区作为次级信息；移除未读、已读、稍后提醒和冗余说明。下方标为“下一次重置预测”，仅保留 24/48 小时概率，不再展示模型、置信度及更新时间。扩展弹窗固定 360px 宽，顶部保持单行，说明页采用紧凑列表，设置页缩短行高和控件高度，集中展示状态、时间与概率；刷新按钮在检查期间旋转；支持浅色和深色主题，默认跟随系统，可在设置中切换并保存。日期、“今天”的判断和时区均跟随浏览器；24 小时概率不等同于本地今天剩余时间的概率。

支持简体中文、英文、日文、西班牙文及阿拉伯文，默认跟随浏览器语言，顶部可切换并保存。界面、通知、工具栏文案及日期格式同步切换；阿拉伯文支持 RTL。来源原文保持原语言。扩展名称和说明也提供 Chrome 原生本地化资源。

[首页预览](docs/popup-preview.png) · [深色预览](docs/dark-preview.png) · [设置预览](docs/settings-preview.png)。截图使用模拟数据。

打开弹窗会优先显示上次成功缓存，随后在后台更新。请求失败时保留缓存，左下角显示最后成功更新时间；过期缓存不会触发新通知，工具栏仍用灰色 `?` 提示非实时状态。首次使用尚无缓存时需等待首次成功获取。

### 开发与验证

需要 Node.js 22 或更新版本；打包还需系统自带的 `zip`。

```sh
npm test          # 数据规则、请求策略、后台提醒流程
npm run check    # 清单、资源、语法和弹窗绑定
npm run pack     # dist/Codex-Reset-0.2.0-插件上传包.zip
```

打包文件包含可加载的扩展目录内容，解压后按上述方式加载。本地源码无需打包即可使用。

Chrome 应用商店上架文案、隐私声明、权限用途说明和图片上传清单见 [上架说明与五语文案](store/01-上架说明与五语文案.md)、[隐私政策](store/02-隐私政策-中英双语.md)、[隐私实践填写稿](store/03-隐私实践-权限填写.md)。上传包由 `npm run pack` 生成；商店图片由 `npm run test:ui` 更新界面截图后，再运行 `npm run store:assets` 生成。商店图片使用测试示例数据，不代表实时预测。

可选浏览器检查：安装 Playwright 后执行 `npm run test:ui`（也可通过 `PLAYWRIGHT_MODULE`、`CHROME_EXECUTABLE` 指向已有安装）。覆盖五种语言、三个页面、RTL、本地时区、紧凑高度、语言持久化和设置交互。

代码入口：`extension/background.js`（后台与提醒）、`extension/api.js`（请求与限流）、`extension/model.js`（状态规则）、`extension/popup.html`（弹窗）。接入依据及已知限制见 [数据源记录](docs/data-source.md)。

系统通知与提示音是否成功，需在真实 Chrome 安装后验收。自动化测试使用模拟 Chrome API；浏览器弹窗检查使用模拟数据，不能代替系统通知验证。
