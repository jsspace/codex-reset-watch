# 数据源接入记录

核实时间：2026-10-28。数据由独立社区项目 [codex-reset.com](https://codex-reset.com/) 提供，与 OpenAI 无隶属关系。

## 公开契约

依据 [开发者文档](https://codex-reset.com/developers/)：无需密钥、支持 CORS；只调用 GET；每个端点最多每分钟读取一次；遵守 `Retry-After`。所有展示数据的界面必须提供来源链接；服务端读取者需要带项目身份的 User-Agent。本扩展在浏览器端直接读取，不代理、不收集账户信息，保留浏览器原生 User-Agent。

| 接口 | 使用字段 | 用途 |
| --- | --- | --- |
| `/api/forecast` | `probabilities.rounded_24h`、`rounded_48h`、`confidence`、`updated_at`、`last_reset_at`、`official_signal` | 24/48 小时预测、近期官方信号与历史记录 |
| `/api/timeline` | `events[].id`、`announced_at`、`announcement_state`、`group`、`summary`、`url`、`updated_at` | 公告识别、原文链接、事件去重 |

不会使用非稳定的分类器字段或内部 alert 决策。特别是 `signal_percent` / `signal_score` 不作为概率使用。

## 状态语义

- **预测**：今天没有重置记录时，角标在 `rounded_24h` 达到 90% 时显示 `今`，否则 `rounded_48h` 达到 90% 时显示 `明`，其他情况直接展示 `rounded_24h`。今天已有记录时，后续预测达到 90% 则优先显示 `明`，否则保留 `今`。预测的日期字只是滚动 24/48 小时窗口的简写，不是按自然日统计的概率，也不是确定日期；悬停说明写明实际窗口。弹窗另列两项概率，时间使用浏览器本地时区。
- **信号**：当前 `official_signal` 比最近重置记录更新，且不超过 24 小时。单独提示，工具栏仍显示模型概率。
- **已宣布**：timeline 明确给出 `group=reset` 且 `announcement_state=announced`，发布时间不超过 24 小时。它用于判断本地今天是否已有重置记录，也用于弹窗、通知和原文链接。较旧记录仅用于详情与判断信号是否失效。
- **已执行**：当前稳定文档没有足够的、独立的执行证据字段。本版本不生成此状态，不依据倒计时归零、概率上涨、故障恢复或第三方公告推断账户已重置。
- **Banked reset**：不属于本版本的全局直接重置提醒，不改变全局公告状态。
- **未知**：请求失败、JSON 不符合约定、来源标为 stale、时间异常、发布副本过期或本地缓存过期。工具栏显示灰色问号，不发旧消息提醒；弹窗保留上次成功快照，左下角显示上次成功更新时间。没有可用缓存时才显示未知。

## 本地缓存

每次成功校验的快照立即写入 `chrome.storage.local`，与最后成功获取时间一起持久保存。打开弹窗先读取本地缓存，再异步请求后台检查；后台 `state` 消息立即返回已有状态，不等网络。刷新完成后，弹窗通过 `chrome.storage.onChanged` 自动接收新数据。旧的磁盘读取结果不会覆盖已经到达的后台更新。

失败、超时、限流或副本过期均不覆盖成功快照，也不会推进最后成功时间。弹窗允许回看过期缓存，现有左下角时间体现数据年龄，连接状态点变灰；布局不变。工具栏和通知保持严格有效期检查，缓存保留不延长原始有效期。损坏、不符合数据结构或含不安全链接的缓存不展示。

## 有效期和请求策略

检查频率一分钟。遵守响应中的 `x-published-checked-at` 和 `x-published-expires-at`；实际读取确认它们为 ISO 时间。无有效期头时，使用两份 JSON 更新时间中较早值加 15 分钟作为保守上限。即使刚发出的请求成功返回，旧数据也不重新获得有效期。

HTTP 429 优先按 `Retry-After` 秒数或 HTTP 日期暂停，缺失时退避五分钟。暂停期间手动刷新也不能越过限流。其他失败一分钟后重试。每次请求超时 12 秒，不携带 cookies、不跟随重定向。Chrome 完全退出或设备休眠时无法保证按时检查；启动后重新检查、恢复闹钟。

按公告 ID、信号 ID 或最近重置周期去重，已读/稍后提醒写入本地存储，最近保留 100 条投递记录。模型概率变化不重复制造新事件。重复提醒默认关闭；开启后也只对有效且未读的消息生效。

桌面通知附来源地址与原文地址；系统是否完整展示这些文字、通知按钮或持续通知由操作系统决定。工具栏悬停说明标明来源；点击后的弹窗在数字下方提供可点击来源署名。

## 验证范围

已实际读取公开 forecast、timeline 响应及发布有效期头，并用真实 JSON 检查归一化结果。单元测试覆盖主要数据与提醒规则；模拟 Chrome API 的后台测试覆盖轮询节流、存储、去重、已读、稍后提醒及失败恢复。桌面系统通知和后台音频仍需在安装后的真实 Chrome 中验收。
